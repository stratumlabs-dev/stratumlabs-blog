Zero-Downtime Blue/Green Deployments on AWS ECS with Terraform and CodeDeploy

By Stratum Labs (contact.stratumlabs@gmail.com)

In modern cloud architecture, deploying new code without dropping user connections is a baseline requirement. When running containerized workloads on AWS Elastic Container Service (ECS), combining ECS with AWS CodeDeploy enables automated blue/green deployments with zero downtime and instant rollback capabilities.

The Architecture

A blue/green deployment strategy maintains two identical production environments (Blue and Green):

  • Blue: The current running version serving production traffic.
  • Green: The newly deployed version receiving test traffic before cutover.

When integrated with an Application Load Balancer (ALB) and target groups, CodeDeploy gradually shifts traffic from Blue to Green based on predefined rules.

Step 1: Configuring the ECS Service with CodeDeploy

When defining your ECS service via Terraform, you must configure the deployment controller to use CODE_DEPLOY:

resource "aws_ecs_service" "app" {
  name            = "stratum-api"
  cluster         = aws_ecs_cluster.main.id
  task_definition = aws_ecs_task_definition.app.arn
  desired_count   = 3
  launch_type     = "FARGATE"

  deployment_controller {
    type = "CODE_DEPLOY"
  }

  load_balancer {
    target_group_arn = aws_lb_target_group.blue.arn
    container_name   = "web"
    container_port   = 8080
  }

  lifecycle {
    ignore_changes = [task_definition, load_balancer]
  }
}

Step 2: Defining the CodeDeploy Application and Deployment Group

Next, set up the CodeDeploy resources to manage the traffic shifting lifecycle:

resource "aws_codedeploy_app" "ecs_app" {
  compute_platform = "ECS"
  name             = "stratum-ecs-app"
}

resource "aws_codedeploy_deployment_group" "ecs_dg" {
  app_name               = aws_codedeploy_app.ecs_app.name
  deployment_group_name  = "stratum-ecs-dg"
  service_role_arn       = aws_iam_role.codedeploy.arn
  deployment_config_name = "CodeDeployDefault.ECSAllAtOnce"

  auto_rollback_configuration {
    enabled = true
    events  = ["DEPLOYMENT_FAILURE"]
  }

  blue_green_deployment_config {
    deployment_ready_option {
      action_on_timeout = "CONTINUE_DEPLOYMENT"
    }

    terminate_blue_instances_on_deployment_success {
      action                         = "TERMINATE"
      termination_wait_time_in_minutes = 5
    }
  }

  ecs_service {
    cluster_name = aws_ecs_cluster.main.name
    service_name = aws_ecs_service.app.name
  }

  load_balancer_info {
    target_group_pair_info {
      prod_traffic_route {
        listener_arns = [aws_lb_listener.https.arn]
      }

      target_group {
        name = aws_lb_target_group.blue.name
      }

      target_group {
        name = aws_lb_target_group.green.name
      }
    }
  }
}

Summary

By decoupling container scheduling from traffic routing using ECS and CodeDeploy, your engineering team can push updates to production mid-day without user-facing disruption. If any health checks fail during the cutover window, CodeDeploy automatically rolls back traffic to the stable blue environment instantly.
